# 视频检查与安全导入 — 2026-10-03

本轮只改按需检查和导入脚本。检查不会播放视频、改变声音/速度、修改视频或
首帧图，也不影响启动、新聊天、生气、完成或闲置的触发链路。

## 小白怎么用

双击项目根目录 `check-videos.cmd`，检查自启动注册的实际安装目录里的五类视频。
把一个 MP4 拖到它上面，则只检查这段视频。没有活动安装时不会猜测其他副本，
可在 PowerShell 指定 `scripts\Check-Videos.ps1 -VideoRoot 'C:\你的目录\videos'`。

- 通过：这项检查通过，不表示所有播放场景都已人工验收。
- 需检查：例如没有音轨、缺少首帧图、首帧图与视频不一致。
- 故障：例如空文件、损坏、没有视频流或解码明确失败。
- 无法确认：工具缺失、执行超时或输出无法识别，不冒充通过或损坏。

首帧图是同目录下的 `视频名-first.png`。没有它会用黑色过渡，并非不能播放。
检查不仅比较名称，还比较实际解码首帧的尺寸和像素 SHA256；不同尺寸即使
像素数相同也不能算匹配。自己编辑过首帧图时，不一致提示也可能是有意修改。
有音轨不代表内容一定有声音；FFmpeg 能解码也不能替代 Codex/Windows 实际播放。

开发者可以用 `-Json` 读取固定字段。退出码 0 表示完成报告，不表示全部通过。
长视频可用 `-TimeoutSeconds`（1–120 秒）；超时为无法确认，不会无限等下去。
报告含本机路径，不要直接上传公开社区。

## 可选工具在哪里

默认查找顺序：显式 `-FFmpegPath` / `-FFprobePath`（无效时不偷偷回退）、
`%USERPROFILE%\.codex-boot-animation\tools\ffmpeg\bin`、兼容旧的
`%LOCALAPPDATA%\CodexBootAnimation\tools\ffmpeg\bin`、最后系统 PATH。
只有提供 FFmpeg 时，可以查找其相邻的 ffprobe。检查器不会自动下载。

本机用户单独批准后准备了 FFmpeg/ffprobe 9.0.2 essentials：官方
[FFmpeg 下载页](https://ffmpeg.org/download.html) 指向
[Gyan Windows 构建](https://www.gyan.dev/ffmpeg/builds/)，下载使用该提供方的
[公开发行镜像](https://github.com/GyanD/codexffmpeg/releases/tag/9.0.2)。
完整 7z 的 SHA256 与提供方校验一致：

```text

ffmpeg.exe: 3256173F3F8BFFD7DF12227C68ADF68025EDB1832273A9530688A7BB1ED8EDEC

```

工具与 LICENSE/README 保存在共享目录，未修改 PATH。构建是 GPLv3，不能因项目
代码用 MIT 就把它当 MIT 发布；本轮没有将工具加入 Git 或发布包。失败/不完整
下载未执行，临时产物保留未删。

用户首次外部双击找不到工具，而打包 Codex 内部测试可见。诊断发现 AppData 被
重定向到应用专属 LocalCache。已复制上述校验过的工具和许可到 UserProfile
共享目录，保留旧文件、不改播放器运行状态。这一问题说明内部测试不能代替
用户从 Explorer 启动的测试。检查模块只由显式检查/导入脚本加载，不被常驻助手
或触发钩子加载，不增加触发延迟。

## 导入时的保护

`Add-Video.ps1` 检查来源后复制；明确故障会拒绝复制。工具缺失或超时则保留
原来的“复制并警告”行为，不能宣称已经验证可播放。拒绝同名视频以及孤立的
同名首帧图，不覆盖文件。原视频不转码；首帧提取有超时且使用禁止覆盖选项。
首帧提取失败时视频可能已经导入，图可能不完整，须再检查，脚本不自动删除。

默认目标仍是当前源码项目的 `plugins\codex-boot-animation\videos`。
本机运行安装是另一目录时，须显式 `-VideoRoot 'C:\实际安装\videos'`，
不要把“已复制到项目”误认成“运行助手已更新”。总是核对打印出的目标路径。
