## 交付规则

1. 先按原规则判断完成任务，在会话锁内保存匿名任务关联和交付预留。
2. 离开会话锁后发送；最多初次加两次重试。截止时间从预留开始计算，
   当前进程还以单调时钟约束重试预算，不因重复事件或重启无限延长。
3. 专用 `--completion-host` 仍复用 CompletionPlayback 的前台 Codex 窗口／后台非激活提醒。
   只有完成窗口首次出现播放进度后，接收器才持久保存 accepted 确认。
   第二个不同任务仅在同一自动提醒仍活动时记为 merged，不打开第二个视频或长队列。
   手动预览占用的窗口不冒充自动完成提醒；媒体缺失、关闭、禁用、暂停不冒充成功。
4. 接收确认先保存后回包。回包丢失时发送端读同一确认，不重复起播。
   只有确认后才按旧格式 claim/consume；失败保留候选，明确记 failed，不再迟到追播。
   用户起画前点跳过/Esc，专门记 dismissed；不把主动跳过当失败而重新弹出。
5. 匿名 final→origin 关联独立保存：已有确认但发送端未清理时，可恢复去重，
   不错把旧完成事件关联到后来输入的任务，不删除后来输入的候选。
6. 如果仅保存关联、尚未预留就崩溃，重复事件按失败关闭，不自动重新开启预算。
   此处优先不误播、不误消耗新任务，不承诺崩溃或断电情况下每条通知都能送达。

原 V2 常驻管道及旧 `__task_complete__`、`--task-play` 兼容入口保留，正常自动完成走新通道。
选择 Run 项注册的安装 EXE，确保可编辑视频目录仍生效；只有与发送 EXE 字节一致才启动。
不一致或注册命令不符合既有格式则拒绝，避免旧 EXE 将新模式误识别成片头。
新通道复用已有当前用户 SID/Windows 会话命名与管道 ACL、限定输入和有界等待。
没有新增后台常驻服务、UIA、键盘/鼠标监控或 Codex 网络连接修改。

两秒是交付尝试/管道等待的程序预算，不是 Windows 实时保证；
系统调度、文件写入和进程创建无法在普通用户态强制保证绝对耗时。
accepted 表示播放器报告首次播放进度，不保证硬件最终显示了每一帧或播到结尾。
dismissed 仅表示用户主动跳过，不冒充视频已经正常播放；其他任务不继承该跳过。
真实画面、听感、焦点和正常结束仍需下一轮验收；没有承诺永久零丢失或严格全局 exactly-once。
