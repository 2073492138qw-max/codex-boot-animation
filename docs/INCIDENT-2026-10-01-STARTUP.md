# 2026-10-01：Codex 启动闪屏停留 / 黑屏排查

## 初始诊断与边界（实施前记录）

用户报告另一位 agent 停止片头助手后重启 Codex，恢复完整界面。本轮没有重启 Codex，
没有启动助手，没有修改数据库、应用包、注册表、hook 定义或信任设置。
片头助手干扰启动是首要嫌疑，但尚未做修复后的同条件对照，不能写成已彻底解决。

## 已核对证据

- 本轮 Codex 主进程与 app-server 在运行，BootPlayer 常驻进程为零。
- Windows Run 的 CodexBootAnimation 项仍在，指向实际安装目录的 `--supervise`。
  停进程不等于永久停用；下次登录可能再次启动旧行为。
- 片头共享日志：11:13、11:17（本地时间）助手启动；11:14、11:19、11:37 检测到
  Codex 实例并播放冷启动。按钮扫描反复返回 count=0，约每 0.3 秒扫描一次，直到 11:43。
- `IntroWatcher.Check / RefreshNewChatButtons` 在主轮询线程同步执行
  `AutomationElement.FromHandle + FindAll(TreeScope.Descendants, Button)`。
  没有启动就绪门槛、扫描耗时上限或失败熔断。窗口出现不等于前端已加载。
- Codex 当日启动日志单独记录了一次 `failed to initialize sqlite state runtime`，
  app-server code=1。它与之后前端停在闪屏不是同一份证据，不能合并成数据库损坏。
  其他 agent 报告数据库完整性正常，本轮未写入或修复数据库。
- 01:30 的 .NET 崩溃栈是 `CompanionLifetimeTests.Parent -> LaunchDetached`，
  路径为源码构建 EXE；是测试夹具失败，不能作为生产播放器崩溃的证明。
- SessionStart 配置为 `async: true, timeout: 130`，命令只恢复助手；
  不能仅凭超时数值宣称前端同步等待 130 秒。
- 源码、实际安装、已信任缓存的 EXE 哈希相同，均为此前共享数据迁移版本。
  其他 agent 没有改变这三份二进制。本轮 Git 未见其代码修复。

## 为什么先修启动干扰

生命周期修复让助手在 Codex 完全退出后仍存活，Windows 登录时也会运行。
原先的全树扫描因此会覆盖真实冷启动阶段。只验“程序已打开时按钮能识别”，
遗漏了“助手先运行、Codex 再冷启动”的路径。降低轮询频率或增加固定等待，
不能证明启动安全，也不能满足用户即时点击的目标。

## 最小方案（用户回复“完善插件”后实施）

1. 移除启动阶段和 count=0 后的无限全树扫描；按钮发现必须有就绪门槛、有限预算、
   隔离执行和失败熔断。未就绪/失败时不继续轰击 Codex 前端。
2. 保留已缓存按钮位置的鼠标点击快路径，不在点击时扫描整个界面。
   布局变化使缓存失效时重新校验；不使用固定坐标误触发托盘或其他控件。
3. 冷启动检测与按钮识别分离。保留视频、场景、速度、音量、窗口布局及任务规则。
4. 增加就绪/熔断逻辑回归；部署前备份，只重启助手。完整退出/重开 Codex 的
   对照测试需用户另行确认，不通过不能提交“修复完成”。

方案属于中风险跨文件功能修改。用户已确认执行；尚未重启 Codex。

## 本轮实现及验证（部署时记录，验收见下节）

- 暂时移除且仅移除 HKCU Run 的 `CodexBootAnimation` 值。原注册表备份在本机
  `%USERPROFILE%\.codex-boot-animation\backup\startup-safety-20261001\Run-before.reg`。
  备份含其他 Run 值，恢复时只恢复该助手值，不要整份导入覆盖其他软件设置。
- `NewChatDiscovery.cs` 独立承载就绪判断、有限扫描、进程隔离、失败状态及回归。
  仅当当前真实 Codex 进程的导航日志证明前端工作，并且窗口在前台且未最小化时扫描。
  Windows 包内和包外日志均观察，文件名 PID 和日志时间必须匹配当前进程，旧日志不作就绪依据。
- 不再使用全树 `FindAll(Descendants)`。子进程只遍历导航区域，限制 160 节点、12 层、
  400ms；子进程 watchdog 1000ms，父进程等候上限 1200ms。超时/错误即熔断，
  普通空结果最多两次，相隔至少三秒。主监控与鼠标钩子不等待 UIA 调用。
- 移动/缩放期间返回的旧矩形丢弃，不算提供器失败，不导致永久误熔断。
  点击仍只查已验证的矩形缓存，原点击延时、播放器与各场景规则未修改。
- `Update-Companion.ps1 -KeepStartupDisabled` 支持已停用登录启动的安全更新；
  失败恢复备份 EXE，但不再自动启动有风险旧版。默认更新路径仍保持原行为。
- PowerShell 7 中共 19 项非 UI 检查通过（15 个 EXE 模式、hook 往返、三组安装检查）。
  新回归覆盖一万次未就绪 tick 不扫描、空结果停止、超时熔断、前台/最小化门槛、
  PID/时间校验、连续移动不误熔断，以及真实子进程卡住后终止。
  Windows PowerShell 5.1 单独执行被本机脚本执行策略拦截；没有改变策略或绕过安全设置，
  本轮不把 5.1 检查写成通过。
- 实际运行：两个按钮成功发现，遍历约 63–64 节点，扫描约 79–151ms；没有持续扫描。
  Computer Use 实际点击新聊天三次，均进入 resident 播放；视频截图确认可见画面。

  对应播放日志记录进度与正常结束。没有物理扬声器声音的人工确认，也未新测物理 Esc。
  最终一次细修后已重新运行全部非 UI 检查，实装再次识别两个按钮。
